B. BUGS IN THE GUI
------------------------------------------------------------------

B1. Retinotopic maps: shape mismatch
    intrinsic/analysis.py, IntrinsicWindow.compute_retinotopic_maps
    On physion_Demo-Datasets/PV-WT/retinotopic_mapping/PVTOM_BB_5:
      ValueError: operands could not be broadcast together with shapes
      (64,80) (128,160)
    Probably two maps computed at different spatial resolutions
    (spatial subsampling of one of them). Phase maps and area segmentation
    run fine.

B2. Calendar: scanning a folder with compressed-imaging NWB files fails
    gui/calendar.py, CalendarWindow.scan_folder
    On physion_Demo-Datasets/PYR-WT:
      ValueError: invalid literal for int() with base 10: 'Ch2'
    The ".nwb" files of the "nwb-xxx/" folders (compressed 2P data, e.g.
    nwb-11142025-001/Ch2-Green-plane0.nwb) are parsed as session files
    (date from the file name). -> skip the folders of
    physion.imaging.folders (compressed_folder / "nwb-" prefix), or only
    take the files named like sessions.

B3. Raw-data window: "faceMotionContour" is never created
    dataviz/gui.py, VisualizationWindow.init_panel_imgs / init_image_panels
    uses self.faceMotionContour, but the panel code creates
    self.whiskContour (probably the same thing renamed) -> AttributeError
    when these functions run.

B4. Whisker maps (somatosensory intrinsic): two versions of the same functions
    intrinsic/SS_analysis.py keeps its own copies of 11 functions of
    intrinsic/analysis.py (set_pixROI, moved_pixels, update_img, update_img1,
    update_img2, update_imgButtons, reset, show_raw_data, get_datafolder,
    pdf_intrinsic, get_pixel_value). The buttons of the window use the
    retinotopy versions, but the SS functions calling them directly use the
    SS copies. 3 copies differ:
      - update_img: the retinotopy version also handles phase maps
      - show_raw_data: different spectrum computation
      - pdf_intrinsic: the SS version adds "--output <folder>/<subject>.pdf"
    -> decide which versions the window should use, delete the others.
    (This behaviour was kept exactly as it was.)

B5. Retinotopy: ROI "remove" action
    intrinsic/analysis.py: self.ROI.sigRemoveRequested.connect(
    lambda: self.remove(self)) -> no "remove" method (AttributeError when
    removing the ROI from its context menu).

B6. Retinotopy used a box of the Ocular-Dominance window
    add_gui_shift_to_images reads self.phaseMapShiftBox, only created by the
    OD analysis window (its creation is commented out in the retinotopy
    window). It now always takes the "no shift" path (error message
    "Pb with altitude, azimuth shift"). -> recreate the box in the
    retinotopy window if the shift is still needed, or remove this code.

B7. Ocular dominance: calc_OD reads threshBox / ipsiBox, whose creation is
    commented out (its button is commented out too: dead code for now).

B8. Space shortcut opens "Build NWBs from DataTable"
    gui/main.py, MainWindow.hitting_space: a debug leftover. In every tab
    without its own [Space] action, pressing Space opens that window.

B9. 2P conversion window: the "rm raw ?" checkbox does nothing
    utils/compression/twoP.py: it is not connected to any code. (To delete
    the tiffs after conversion, use Convert-TSeries-to-h5.py in yann/.)

B10. Episodes of some 2022 NWB files cannot be built
    EpisodeData fails on:
      Yann/VIP-CB1-OctNovDec-2022/2022_10_26-17-08-32.nwb and 18-05-07
      Marcel/SST-TdTomato-December-2022/2022_11_28-13-38-54.nwb and 13-49-06
        -> "2 indexing arguments for 1 dimensions" /
           "Use other code for boolean selection on 1D dataset"
           (1D stimulus datasets in old files, 2D "(n,1)" expected)
      Adrianna/conversion-ABF+TSeries-to-NWB/... -> KeyError 'time_start'
    and two files cannot be loaded at all:
      Yann/Pyr-FlexiCortPrelim-FebJuly-2022/2022_03_07-16-06-07.nwb, 2022_03_16-16-21-18.nwb
        -> KeyError 'CaImaging-TimeSeries'
    (continuation of the "backward-compatibility" work)

B11. Pupil fit vs saved pupil.npy
    The fit of the pupil window differs by a few pixels from the stored
    pupil.npy of the demo session, even with the same settings (smoothing,
    reflectors). Most likely the imprecise frame reading in .wmv videos
    (physion warns about it); worth a check with a binary/converted movie.
